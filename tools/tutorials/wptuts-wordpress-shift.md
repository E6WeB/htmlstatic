## Overview

In this video, Paul Charlton from **WPTuts** examines the macro shift happening across web design. As AI tools rewrite the rules of building websites, developers and agencies are questioning whether managing complex WordPress databases, constant plugin updates, security patches, and heavy page builder abstractions still makes sense for brochure and client sites.

The guide breaks down whether it still makes sense to stick 100% with WordPress, take a hybrid headless approach, or move projects entirely towards static-first architectures—especially since AI coding tools struggle with the proprietary abstractions introduced by legacy page builders.

---

## Featured Tools in This Video

The walkthrough showcases four modern static-first and visual builders:

1. **[Sitereal](../development-tools/sitereal.md)**: An offline desktop app (Mac/Windows) featuring visual drag-and-drop editing, local Markdown/CMS collections, AI component generation, and native Astro code output.
2. **[Instatic](../content-management/instatic.md)**: A free, browser-based visual builder built by the Core Framework developers, offering clean utility workflows and AI generation.
3. **[Stacki](../content-management/stacki.md)**: A Webflow-familiar visual site builder offering both local and collaborative static web workflows.
4. **[Phantom Studio](../content-management/phantom-studio.md)**: A visual builder designed to give WordPress creators a familiar experience while producing fast, secure static sites.

---

## Key Takeaways

1. **Reduced Maintenance Burden**: Static websites eliminate MySQL databases, constant core/plugin update anxiety, and common security vectors.
2. **AI Synergy**: AI coding models work best with clean, standard HTML, CSS, and Astro components—not locked inside proprietary WordPress shortcodes or database postmeta blobs.
3. **Hybrid & Gradual Adoption**: You don't have to abandon WordPress overnight; you can use headless backends or transition brochure and portfolio projects first.
